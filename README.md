# MENU RUMBLE · 메뉴 럼블

오늘의 메뉴를 작은 입체 캐릭터들의 **자동 난투전**으로 정하는 브라우저 게임입니다.

- 승인한 캐릭터 디자인: 둥근 구형 머리, 단색 블록 몸통, 짧은 팔다리
- 비스듬히 내려다보는 3D 경기장, 캐릭터 걷기·공격 동작, 바닥 그림자
- 메뉴별 출전 수 **1–40마리**, 메뉴 **2–16개**, 전체 **최대 160마리**
- 기본 8개 메뉴 × 5마리 = 40마리의 난투전
- 수량 버튼 또는 `치킨*10, 피자*2` 형식으로 메뉴와 출전 수 입력
- `내 메뉴 만들기`에서 기본 메뉴 대신 원하는 메뉴를 한 번에 입력하고 바로 적용
- 이름을 붙인 개인 메뉴 모음을 이 브라우저에 저장하고 다시 불러오기
- 숲속 유적 / 모래 경기장 / 달빛 정원 맵 선택
- 자동 이동, 돌진, 회피, 치명타, 밀쳐내기, 범위 반격
- 메뉴별 맨손 / 짧은 검 선택: 짧은 검은 공격력 10% 증가
- 시작 전 메뉴별 추정 승률: 출전 수·무기·맵에 따른 가상 전투로 계산
- 일시정지, 1–3배속, 효과음, 재대결, 결과 복사, 최근 20개 기록
- 메뉴·출전 수·맵·기록은 현재 브라우저에 저장
- 모바일 터치 화면, 하단 시작 버튼, 경기장 집중 모드, 가로 화면 지원
- 휴대폰에서는 캔버스 표시를 초당 30회로 제한하고 이펙트를 줄이며, 전투 계산 규칙은 동일하게 유지

## 승부 방식

**우승 메뉴를 미리 추첨하지 않습니다.** 캐릭터들이 실제로 이동하고 체력을 주고받으며, 마지막까지 캐릭터가 남은 메뉴가 우승합니다. 같은 메뉴끼리는 공격하지 않습니다.

모든 캐릭터에 같은 체력과 전투 규칙을 적용합니다. 출전 수가 많으면 보통 유리하지만, 정확한 승률이 수량 비율과 같지는 않습니다. 회피·치명타·범위 공격·공격 타이밍이 무작위로 달라집니다. 주변 적이 많으면 범위 반격이 빨리 충전되고, 범위 반격에는 강력한 일격이 나올 확률이 있어 소수 팀도 역전할 수 있습니다. 이 규칙은 모든 캐릭터에 동일하게 적용합니다.

24초부터 안전 구역이 좁아져 전투가 끝없이 늘어지는 것을 방지합니다. 맵·출전 수·위치·전투 상황에 따라 승률은 달라집니다.

### 무기와 추정 승률

짧은 검의 보너스는 **공격력 ×1.1**입니다. 체력은 그대로이며 승률이 10%포인트 오른다는 뜻은 아닙니다. 검을 든 팀도 실제 전투에서 질 수 있습니다.

추정 승률은 브라우저의 별도 Web Worker에서 본 경기와 같은 규칙으로 독립적인 전투를 반복해 계산합니다. PC는 최대 128회, 휴대폰은 최대 64회이며 80마리를 넘는 경기에서는 각각 48회와 24회로 제한합니다. 먼저 최소 8회의 결과를 보여준 뒤 시작할 수 있습니다. 계산 횟수를 화면에 표시하며, 표본이 적을수록 오차가 큽니다. 유한한 표본에서 0승이 곧 승리 불가능을 뜻하지 않도록 각 팀에 작은 동일 보정값을 적용합니다.

이 수치는 **현재 조건의 시뮬레이션 추정치**이고, 실제 승률을 보장하지 않습니다. 본 경기는 계산용 전투와 별개의 난수를 쓰고, 우승자를 미리 정하지 않습니다. Worker를 지원하지 않으면 추정 표시만 생략하고 전투는 진행합니다.

## 무료 운영

유료 AI API, 유료 게임 에셋, 별도 게임 서버를 사용하지 않습니다. 전투·3D 렌더링·승률 계산은 방문자의 브라우저에서 실행됩니다. Three.js와 개발용 압축 도구 esbuild는 MIT 라이선스이며 Three.js 라이선스를 `dist/vendor/three.LICENSE.txt`에 포함합니다. 이미 준비된 `dist/`에는 외부 CDN 연결 없이 실행할 라이브러리가 들어 있습니다.

공개 저장소에서는 GitHub Free의 GitHub Pages로 정적 호스팅할 수 있습니다. 저장소에 파일을 올린 뒤 Pages의 배포 소스를 `main` 브랜치와 `/(root)`로 선택하면 루트 페이지가 `dist/`로 연결됩니다. `.nojekyll`도 포함되어 있습니다. [GitHub Pages 공식 안내](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)

## 실행

Node.js 20 이상에서 미리 준비한 파일은 별도 패키지 설치 없이 실행합니다.

```sh
npm run dev
```

브라우저에서 `http://127.0.0.1:4173`을 엽니다. 다른 포트는 `PORT` 환경 변수로 지정할 수 있습니다.

## 검사

```sh
npm run check
npm test
node scripts/check-underdog.mjs
```

자동 검사는 수량 입력, 입력 범위, 같은 메뉴 간 공격 금지, 세 맵의 전투 종료, 160마리 경기, 정지 상태, 그리고 실제 10 대 2 역전승 사례를 확인합니다. `check-underdog.mjs`는 고정된 여러 난수 시드로 전투를 재현하는 진단 스크립트이며, 결과를 실제 서비스의 확률 보장으로 사용하지 않습니다.

3D 모델 용량을 다시 최적화할 때만 개발 의존성을 설치합니다.

```sh
npm ci
npm run vendor
```

## 파일 구조

```text
dist/
  index.html     페이지와 컨트롤
  style.css      반응형 화면
  app.mjs        메뉴·수량·맵·게임 상태 연결
  engine.mjs     DOM과 독립적인 전투 시뮬레이션 및 맵 데이터
  renderer-3d.mjs 3D 렌더링과 2D UI 오버레이
  scene-model.mjs 구형 머리·블록 신체·무기의 모델 및 경기장
  renderer.mjs   호환용 2D 보기 및 맵 미리보기
  odds.mjs       독립 가상 전투를 통한 승률 추정
  odds-worker.mjs 계산용 Web Worker
  vendor/        최적화한 무료 라이브러리와 라이선스
scripts/
  dev.mjs        로컬 정적 서버
  check-underdog.mjs
tests/
  engine.test.mjs
.openai/
  hosting.json   Sites 배포 정보
```

새 맵은 `engine.mjs`의 `MAPS`에 팔레트와 장애물 좌표를 추가하면 맵 선택 목록에도 표시됩니다. 외부 게임의 이미지나 스프라이트를 사용하지 않으며 게임 그래픽은 코드로 그립니다. WebGL 2가 없으면 간단한 2D 보기로 실행합니다. 글꼴은 Google Fonts를 사용하고 연결되지 않으면 시스템 글꼴로 표시합니다.

## 자원 관리와 보안 검사

메뉴 이름은 textContent/Canvas 텍스트로 출력하며 HTML로 실행하지 않습니다. 승률 계산은 최대 128회, 참가자는 최대 160마리로 제한합니다. 승률 캐시 12개, 기록 20개, 내 메뉴 모음 20개, 3D 맵 캐시 3개와 화면 효과 개수를 제한합니다. 탭을 숨기면 RAF와 계산 워커를 중단하며, 복귀하면 필요한 계산만 다시 시작합니다. BFCache 복귀는 지원하고, 페이지 종료 시 공유 GPU 자원과 WebGL 컨텍스트 및 오디오를 정리합니다.

2026-10-23 기준 npm audit에서 알려진 의존성 취약점 0건, 자동 검사 31개 통과. 이 검사는 전체 보안 감사나 실제 휴대폰 장시간 힙 프로파일링을 대체하지 않습니다. 메뉴와 기록은 브라우저 localStorage에 저장하므로 비밀 정보 보관 용도로 사용하지 않습니다.

## 지형이 다른 경기장

기존 숲속 유적·모래 경기장·달빛 정원에 얼음 호수·용암 분화구·해적선 갑판을 추가해 총 6개 맵을 제공합니다. 얼음 호수는 두 빙판을 좁은 다리로 연결하고 전투 AI가 다리 입구로 이동합니다. 용암 분화구는 중앙 바위를 둘러싼 순환 지형이며, 해적선은 화물과 양끝이 좁아지는 갑판을 가집니다. 물·용암은 경기장 바깥의 배경이며 추가 피해 효과는 없습니다.

새 맵의 `terrain` 다각형은 생성 위치, 이동·넉백 충돌, 3D 바닥, 2D 미리보기가 공유합니다. GPU 맵은 최대 3개를 보관하고 나머지는 자원을 해제합니다. 모든 맵에서 최대 160마리 전투 및 지형 이탈 방지를 검사합니다.

## 화면 시인성

캐릭터 머리 위 메뉴 이름 대신 경기장 상단의 색상·메뉴·생존 수 범례를 사용합니다. 크게 보기에서도 범례와 경기장을 함께 표시합니다. 기본 캐릭터는 PC 1.35배, 모바일 1.55배로 표시하며 80마리를 넘으면 혼잡도를 줄이기 위해 배율을 낮춥니다. 체력과 공격 판정은 바뀌지 않습니다. 어두운 외곽선과 팀 색상 바닥 링을 추가하고 바닥 대비와 숫자 효과를 줄였습니다. 화면 장식과 중복 문구를 정리하고 메뉴·맵 카드의 간격을 맞췄습니다.
